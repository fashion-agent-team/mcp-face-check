# 공개 데이터셋(CelebA)으로 정한 비대칭 기준값 (2026-11-09)

팀 셀카에 라벨을 붙이기 전까지 쓰는 기준입니다. 라벨 붙인 셀카가 모이면 `train.py`로 다시 학습해서 바꿉니다.

## 방법

1. **데이터**: [CelebA](https://mmlab.ie.cuhk.edu.hk/projects/CelebA.html). 사진 20만 장에 사람이 붙인 속성 라벨 40개가 있고, 그중
   `Heavy_Makeup`(화장 진함), `Wearing_Lipstick`(립스틱)이 있습니다. 원본 크기 사진(`img_celeba`) 처음 15,000장과 같은 사람 비교용으로 더 받은 2,697장(`per_person_baseline.py`)에서
   화장했고 립스틱을 발랐고, 앞머리·안경·모자·흐림이 없고, 얼굴 상자가 180px 이상인 여성 사진 4,657장을 골랐습니다.
2. **셀카처럼 맞추기**: 얼굴 상자를 넉넉히 잘라 600x800으로 맞추고, 윤곽점은 앱 ML Kit 대신 MediaPipe로 뽑았습니다.
   고개가 10도 넘게 돌아간 사진(앱에서는 "정면으로" 안내하는 경우)을 빼고 2,832장을 서버로 쟀습니다.
3. **기준값**: 항목마다 측정값의 95번째 백분위. "잘 화장해서 남에게 보인 사진 100장 중 95장보다 더 다르면 말해 준다"는 뜻입니다.
   타고난 얼굴 비대칭, 윤곽점 오차, 조명 차이가 모두 이 범위 안에 들어가므로, 이보다 작은 차이를 말하면 괜히 틀렸다고 하는 일이 잦아집니다.
4. **검출률 확인**: 같은 사진에 한쪽만 다르게 그려 넣고(눈썹 올림, 한쪽 블러셔, 한쪽 립 옅게, 윗입술 선 넘김) 그 기준으로 몇 %를 잡는지 쟀습니다.

다시 돌리기: `python3 fetch_celeba.py celeba` → 서버 띄우기 → `python3 public_baseline.py celeba/home/ubuntu/CelebA --n 5000 --apply`

## 해석

- **눈썹 높이·블러셔는 잘 잡습니다.** 눈썹을 두 눈 사이의 0.08배(약 5mm) 넘게 올리면 94% 넘게, 블러셔를 한쪽에 진하게 바르면 97% 잡습니다.
  눈썹 높이 기준 0.042(약 2.6mm)는 사람이 눈썹 높이 차이를 알아보기 시작하는 3~3.5mm(두 눈 사이 약 62mm 기준 0.05~0.06)와 비슷한 크기입니다
  ([Wang 외 리뷰](https://researchers.mq.edu.au/en/publications/discriminative-thresholds-in-facial-asymmetry-a-review-of-the-lit/),
  [Hohman 외 2014](https://zendy.io/title/10.1002/lary.24331)).
- **입꼬리 기준 0.085(약 5mm)**는 일반인이 입술 기울기를 "어색하다"고 보는 3mm보다 큽니다
  ([태국 교정학회 2025](https://he01.tci-thaijo.org/index.php/THAIORTHO/article/view/276937)). 화장한 공개 사진에서도 웃는 표정이 많아
  원래 차이가 크게 나왔습니다. 앱이 "무표정으로" 안내하면 실제 셀카에서는 더 낮춰도 됩니다.
- **입술 색·입술 선은 재는 방식을 바꿔서 많이 좋아졌습니다**(아래 "개선 기록"). 한쪽 립을 많이 옅게 하면 93%, 윗입술 선을 많이 넘기면 78% 잡습니다.
- **눈썹 두께는 분할 모델로 바꾼 뒤 절반쯤 잡습니다**(한쪽을 많이 두껍게 그리면 50%, 아래 "얼굴 분할 모델").
- **눈썹 길이는 얼굴 반쪽 너비로 나눈 뒤 40%쯤 잡습니다**(한쪽을 많이 짧게 그린 것).
- **입술 반쪽 너비는 윤곽점 입꼬리와 비교한 뒤 40%쯤 잡습니다**(한쪽 입꼬리를 많이 밖으로 그린 것). 아래 "입술 너비" 참고.

## 개선 기록 (2026-11-09)

같은 사진(처음 1,191장)과 같은 그려 넣기로, 기준은 늘 "그려 넣지 않은 사진의 95%는 말하지 않음"에 맞춰 비교했습니다.

| 항목 | 바꾼 것 | 가장 큰 차이 검출률 | 중간 크기 |
| --- | --- | --- | --- |
| lipColor | 좌우 입술 색을 그대로 비교 → 쪽마다 입술 옆 피부와의 색 차이를 구해 그 차이끼리 비교. 한쪽에서 빛이 들어와도 피부도 같이 밝아져 지워짐 | 49% → 97% | 13% → 60% |
| upper/lowerLipLine | 입꼬리를 이은 선에서 두께 → 윤곽점 안쪽 선(윗입술 아래 선)에서 두께, 같은 위치끼리 좌우 비율의 가운데 값, 열마다 끝은 10% 값 | 23% → 75% | 15% → 49% |
| browHeight 등 눈썹 | 어두운 덩어리 중 가장 큰 것 → 윤곽점 눈썹 가로 범위 안(안쪽 0.08,바깥 0.10 여유)에서, 윤곽점 가운데와 가깝고 가로로 긴 덩어리. 꼬리가 끊긴 조각은 같은 높이면 붙임. 머리카락을 눈썹으로 고르던 것이 줄어듦 | 88% → 95% | 42% → 43% |
| browHeight·browTail·browThickness | 밝기로 나누기 → 얼굴 분할 모델(BiSeNet)이 눈썹이라고 한 픽셀. 두께는 가로 위치마다 잰 세로 두께의 가운데 값 | 높이 95% → 100%, 두께 8% → 50% | 높이 43% → 94%, 두께 5% → 38% |
| browLength | 눈 너비로 나누기 → 분할 모델 눈썹 길이 ÷ 같은 높이 얼굴 반쪽 너비(코 가운데 ~ 옆선) | 3% → 42% | 3% → 8% |
| lipHalfWidth | 가운데 선 ~ 입꼬리 길이 비율 → 사진 입꼬리가 윤곽점 입꼬리보다 더 나간 길이(IOD)의 좌우 차 | 20% → 41% | 14% → 21% |

해 봤지만 효과가 없어 뺀 것:
- 눈썹 길이·두께, 입술 반쪽 너비를 다르게 재기 6가지(눈 너비로 나누기, 그대로 길이, 꼬리 끝 위치, 어두운 정도 합, 열마다 두께 가운데 값, 인중 가운데 선 기준 너비). 모두 3~24%로 그대로였습니다.
- 웃거나 입을 벌린 사진을 윤곽점으로 가려(CelebA 라벨로 학습, 정확도 0.80) 무표정 사진만 보기.
무표정 사진만 남겨도 입술 모양의 원래 차이가 거의 줄지 않았습니다(입꼬리 p95 0.085 → 0.072, 입술 선은 그대로).

## 본인 사진과 비교하면 나아질까 (2026-11-09)

`per_person_baseline.py`로 시험했습니다. CelebA에서 화장한 정면 사진이 10장 넘는 사람 300명을 골라(측정된 사진 1,825장),
사진마다 "같은 사람의 다른 사진 3장·5장 값의 가운데 값"을 빼고 비교했습니다. 기준은 똑같이 그려 넣지 않은 사진의 95%는 말하지 않게 맞췄습니다.

| 항목 | 지금 방식 (가장 큰 차이) | 본인 5장 기준 |
| --- | --- | --- |
| browHeight | 100% | 100% |
| browLength | 10% | 3% |
| browThickness | 8% | 4% |
| lipHalfWidth | 24% | 18% |
| upperLipLine | 69% | 57% |
| cheekColor | 98% | 97% |
| lipColor | 89% | 86% |

**나아지지 않았습니다.** 값이 흔들리는 이유를 나눠 보면, 사람마다 원래 다른 몫은 0~20%이고 나머지 80~100%는 사진마다 다른 몫이었습니다
(눈썹 길이 14%, 두께 12%, 입술 너비 20%, 색은 0%). 원래 얼굴이 비대칭이라서가 아니라 사진마다 머리카락·조명·표정·각도가 달라서
흔들리는 것이므로, 같은 사람의 예전 사진을 빼도 흔들림이 줄지 않습니다. 같은 자리에서 찍은 셀카 몇 장끼리라면 조명·머리카락이
같아서 오히려 같은 쪽으로 틀리기 쉬울 것으로 봅니다(시험하지 않은 추측).

그래서 눈썹 길이·두께, 입술 너비를 더 잘 잡으려면 기준값보다 **재는 방법 자체**(머리카락과 눈썹을 나누는 분할 모델 등)를 바꿔야 합니다. → 아래 "얼굴 분할 모델"에서 눈썹 높이·두께는 올랐습니다.

## 얼굴 분할 모델 (2026-11-09)

밝기로 눈썹을 나누면 머리카락·그늘이 섞입니다. 그래서 공개 얼굴 분할 모델 **BiSeNet**(CelebAMask-HQ 3만 장으로 학습, 눈썹·눈·입술·머리카락 등 19가지)을
서버에 넣었습니다(`OnnxFaceParser`, `src/main/resources/models/face_parsing_bisenet_fp16.onnx`, 26MB).

- 얼굴 좌표로 돌려 맞춘 512x512로 넣고(두 눈 사이의 4.2배 정사각형), 눈썹 칸만 골라 높이·꼬리·길이·두께를 잽니다.
- 모델 파일이 없거나 눈썹 칸을 못 찾으면 예전처럼 밝기로 나눠 잽니다.
- 사진 한 장에 CPU로 70~200ms 걸립니다.
- 모델 만드는 법: `export_face_parsing.py`. 공개 Docker 이미지에서 원래 가중치(zllrunning/face-parsing.PyTorch)를 받아 ONNX(fp16)로 바꿉니다.
  모델 구조는 직접 다시 쓰고, 가중치는 코드 실행 없이 숫자만 읽습니다. fp16 결과는 fp32와 같았습니다(int8은 눈썹 모양이 달라져서 쓰지 않음).
- 눈썹 길이: 그대로 재면 고개를 10도 안쪽으로만 돌려도 먼 쪽 눈썹이 짧아 보여서(고개 각도와 상관 0.60) 거의 못 잡았습니다.
  같은 높이의 **얼굴 반쪽 너비(코 가운데 ~ 얼굴 옆선)로 나누면** 먼 쪽 얼굴도 같이 좁아 보여 상쇄됩니다(상관 0.02).
  기준이 0.475 → 0.218로 줄고, 한쪽을 많이 짧게 그린 것 검출이 2% → 42%가 됐습니다.
  눈 너비로 나누기, 꼬리 끝과 눈꼬리 사이, 고개 각도로 직접 보정하기는 효과가 없었습니다.
- 입술 반쪽 너비는 분할 모델이 밖으로 그린 입꼬리를 입술로 거의 안 쳐서(크게 그려도 비율 0.06 변화) 분할 모델로 재지 않습니다.
- CelebAMask-HQ도 비상업 연구용입니다.

## 입술 너비 (2026-11-09)

입꼬리 위치를 사진에서 재면 좌우 차이가 원래 16%쯤 흔들려서(웃음, 고개 돌림, 입꼬리 그늘) 한쪽을 밖으로 그린 것(평균 +0.175)을 잘 못 잡았습니다.
윤곽점 입꼬리는 그린 선은 거의 안 따라가고(+0.024) 웃음·고개 돌림 같은 원래 비대칭은 따라가므로, **사진 입꼬리 - 윤곽점 입꼬리**(쪽마다 "더 그린 길이")를
좌우 비교하면 흔들림이 0.16 → 0.05로 줄고 그려 넣은 차이는 남습니다. 한쪽을 많이 밖으로 그린 것 검출 20% → 41%.
코 가운데 기준, 얼굴 반쪽 너비로 나누기, 둘 섞기, 고개 각도 보정은 24~32%로 이보다 낮았습니다.
누드 립처럼 색으로 입술을 못 나누면 이 항목은 재지 않습니다(윤곽점만으로는 그린 선을 알 수 없음).

## 입꼬리 높이 시험 (2026-11-09, 바꾸지 않음)

한쪽 입꼬리를 위로 올려 그린 것(두 눈 사이의 0~0.1)을 그려 넣어 시험했습니다. 지금 방식은 10~18%만 잡고, 윤곽점 입꼬리 대비·입꼬리 쪽 윗/아랫 가장자리·둘의 가운데로
재는 5가지도 3~14%였습니다. 0.1만큼 올려 그려도 잰 값은 0.02~0.036만 움직이는데, 사진에서 잰 입꼬리 높이는 원래 좌우로 0.04쯤 흔들려서
(입꼬리 그늘, 입 모양) 구분이 안 됩니다. 이 항목은 "아주 심할 때만 말하는" 항목으로 두고, 같은 방식은 더 시도하지 않습니다.

## 한계

- CelebA는 유명인 사진이라 조명·화장이 셀카와 다르고, 서양인 비율이 높습니다. 윤곽점도 ML Kit가 아니라 MediaPipe입니다.
- "화장한 사진은 대부분 고르게 했다"고 보고 정한 값이라, 사람이 "비대칭"이라고 라벨 붙인 데이터는 아닙니다.
  팀 셀카(한쪽만 다르게 그린 것 포함)에 라벨이 생기면 `train.py`로 다시 학습해서 바꾸세요.
- CelebA는 비상업 연구용입니다. 사진은 레포에 올리지 않았고, 숫자(기준값)만 남겼습니다.
