# 공개 데이터셋(CelebA)으로 정한 비대칭 기준값 (2026-11-09)

팀 셀카에 라벨을 붙이기 전까지 쓰는 기준입니다. 라벨 붙인 셀카가 모이면 `train.py`로 다시 학습해서 바꿉니다.

## 방법

1. **데이터**: [CelebA](https://mmlab.ie.cuhk.edu.hk/projects/CelebA.html). 사진 20만 장에 사람이 붙인 속성 라벨 40개가 있고, 그중
   `Heavy_Makeup`(화장 진함), `Wearing_Lipstick`(립스틱)이 있습니다. 원본 크기 사진(`img_celeba`) 처음 15,000장과 같은 사람 비교용으로 더 받은 2,697장(`per_person_baseline.py`)에서
   화장했고 립스틱을 발랐고, 앞머리·안경·모자·흐림이 없고, 얼굴 상자가 180px 이상인 여성 사진 4,657장을 골랐습니다.
2. **셀카처럼 맞추기**: 얼굴 상자를 넉넉히 잘라 600x800으로 맞추고, 윤곽점은 앱 ML Kit 대신 MediaPipe로 뽑았습니다.
   고개가 10도 넘게 돌아간 사진(앱에서는 "정면으로" 안내하는 경우)을 빼고 2,832장을 서버로 쟀습니다.
3. **기준값**: 항목마다 측정값의 95번째 백분위. "잘 화장해서 남에게 보인 사진 100장 중 95장보다 더 다르면 말해 준다"는 뜻입니다.
   타고난 얼굴 비대칭, 윤곽점 오차, 조명 차이가 모두 이 범위 안에 들어가므로, 이보다 작은 차이를 말하면 괜히 틀렸다고 하는 일이 잦아집니다.
4. **검출률 확인**: 같은 사진에 한쪽만 다르게 그려 넣고(눈썹 올림, 한쪽 블러셔, 한쪽 립 옅게, 윗입술 선 넘김) 그 기준으로 몇 %를 잡는지 쟀습니다.

다시 돌리기: `python3 fetch_celeba.py celeba` → 서버 띄우기 → `python3 public_baseline.py celeba/home/ubuntu/CelebA --n 5000 --apply`

## 해석

- **눈썹 높이·블러셔는 잘 잡습니다.** 눈썹을 두 눈 사이의 0.08배(약 5mm) 넘게 올리면 94% 넘게, 블러셔를 한쪽에 진하게 바르면 97% 잡습니다.
  눈썹 높이 기준 0.041(약 2.5mm)는 사람이 눈썹 높이 차이를 알아보기 시작하는 3~3.5mm(두 눈 사이 약 62mm 기준 0.05~0.06)와 비슷한 크기입니다
  ([Wang 외 리뷰](https://researchers.mq.edu.au/en/publications/discriminative-thresholds-in-facial-asymmetry-a-review-of-the-lit/),
  [Hohman 외 2014](https://zendy.io/title/10.1002/lary.24331)).
- **입꼬리 기준 0.085(약 5mm)**는 일반인이 입술 기울기를 "어색하다"고 보는 3mm보다 큽니다
  ([태국 교정학회 2025](https://he01.tci-thaijo.org/index.php/THAIORTHO/article/view/276937)). 화장한 공개 사진에서도 웃는 표정이 많아
  원래 차이가 크게 나왔습니다. 앱이 "무표정으로" 안내하면 실제 셀카에서는 더 낮춰도 됩니다.
- **입술 색·입술 선은 재는 방식을 바꿔서 많이 좋아졌습니다**(아래 "개선 기록"). 한쪽 립을 많이 옅게 하면 91%, 윗입술 선을 많이 넘기면 94% 잡습니다(아래 "입술 선").
- **눈썹 두께는 60%대를 잡습니다**(중간 크기 이상). 사진을 좌우로 뒤집어 한 번 더 나누고 눈썹 칸을 합쳐서 47% → 62%가 됐습니다(아래 "뒤집어 한 번 더 나누기").
- **눈썹 길이는 눈썹 길이 모델로 바꾼 뒤 거의 다 잡습니다**(0.08 넘게 짧게 그리면 97% 이상). 재는 방식으로는 22%가 한계였습니다(아래 "눈썹 길이 모델").
- **입술 반쪽 너비는 입술 너비 모델로 바꾼 뒤 거의 다 잡습니다**(0.03 넘게 더 그리면 91% 이상). 재는 방식으로는 20%가 한계였습니다(아래 "입술 너비 모델").

## 개선 기록 (2026-11-09)

같은 사진(처음 1,191장)과 같은 그려 넣기로, 기준은 늘 "그려 넣지 않은 사진의 95%는 말하지 않음"에 맞춰 비교했습니다.

| 항목 | 바꾼 것 | 가장 큰 차이 검출률 | 중간 크기 |
| --- | --- | --- | --- |
| lipColor | 좌우 입술 색을 그대로 비교 → 쪽마다 입술 옆 피부와의 색 차이를 구해 그 차이끼리 비교. 한쪽에서 빛이 들어와도 피부도 같이 밝아져 지워짐 | 49% → 97% | 13% → 60% |
| upper/lowerLipLine | 입꼬리를 이은 선에서 두께 → 윤곽점 안쪽 선(윗입술 아래 선)에서 두께, 같은 위치끼리 좌우 비율의 가운데 값, 열마다 끝은 10% 값 | 23% → 75% | 15% → 49% |
| browHeight 등 눈썹 | 어두운 덩어리 중 가장 큰 것 → 윤곽점 눈썹 가로 범위 안(안쪽 0.08,바깥 0.10 여유)에서, 윤곽점 가운데와 가깝고 가로로 긴 덩어리. 꼬리가 끊긴 조각은 같은 높이면 붙임. 머리카락을 눈썹으로 고르던 것이 줄어듦 | 88% → 95% | 42% → 43% |
| browHeight·browTail·browThickness | 밝기로 나누기 → 얼굴 분할 모델(BiSeNet)이 눈썹이라고 한 픽셀. 두께는 넓이 ÷ 길이(평균 두께) | 높이 95% → 100%, 두께 8% → 55% | 높이 43% → 94%, 두께 5% → 45% |
| browLength | 눈 너비로 나누기 → 분할 모델 눈썹 길이 ÷ 같은 높이 얼굴 반쪽 너비(코 가운데 ~ 옆선) | 3% → 42% | 3% → 8% |
| lipHalfWidth | 가운데 선 ~ 입꼬리 길이 비율 → 사진 입꼬리가 윤곽점 입꼬리보다 더 나간 길이(IOD)의 좌우 차 | 20% → 41% | 14% → 21% |

해 봤지만 효과가 없어 뺀 것:
- 눈썹 길이·두께, 입술 반쪽 너비를 다르게 재기 6가지(눈 너비로 나누기, 그대로 길이, 꼬리 끝 위치, 어두운 정도 합, 열마다 두께 가운데 값, 인중 가운데 선 기준 너비). 모두 3~24%로 그대로였습니다.
- 웃거나 입을 벌린 사진을 윤곽점으로 가려(CelebA 라벨로 학습, 정확도 0.80) 무표정 사진만 보기.
무표정 사진만 남겨도 입술 모양의 원래 차이가 거의 줄지 않았습니다(입꼬리 p95 0.085 → 0.072, 입술 선은 그대로).

## 본인 사진과 비교하면 나아질까 (2026-11-09)

`per_person_baseline.py`로 시험했습니다. CelebA에서 화장한 정면 사진이 10장 넘는 사람 300명을 골라(측정된 사진 1,825장),
사진마다 "같은 사람의 다른 사진 3장·5장 값의 가운데 값"을 빼고 비교했습니다. 기준은 똑같이 그려 넣지 않은 사진의 95%는 말하지 않게 맞췄습니다.

| 항목 | 지금 방식 (가장 큰 차이) | 본인 5장 기준 |
| --- | --- | --- |
| browHeight | 100% | 100% |
| browLength | 10% | 3% |
| browThickness | 8% | 4% |
| lipHalfWidth | 24% | 18% |
| upperLipLine | 69% | 57% |
| cheekColor | 98% | 97% |
| lipColor | 89% | 86% |

**나아지지 않았습니다.** 값이 흔들리는 이유를 나눠 보면, 사람마다 원래 다른 몫은 0~20%이고 나머지 80~100%는 사진마다 다른 몫이었습니다
(눈썹 길이 14%, 두께 12%, 입술 너비 20%, 색은 0%). 원래 얼굴이 비대칭이라서가 아니라 사진마다 머리카락·조명·표정·각도가 달라서
흔들리는 것이므로, 같은 사람의 예전 사진을 빼도 흔들림이 줄지 않습니다. 같은 자리에서 찍은 셀카 몇 장끼리라면 조명·머리카락이
같아서 오히려 같은 쪽으로 틀리기 쉬울 것으로 봅니다(시험하지 않은 추측).

그래서 눈썹 길이·두께, 입술 너비를 더 잘 잡으려면 기준값보다 **재는 방법 자체**(머리카락과 눈썹을 나누는 분할 모델 등)를 바꿔야 합니다. → 아래 "얼굴 분할 모델"에서 눈썹 높이·두께는 올랐습니다.

## 얼굴 분할 모델 (2026-11-09)

밝기로 눈썹을 나누면 머리카락·그늘이 섞입니다. 그래서 공개 얼굴 분할 모델 **BiSeNet**(CelebAMask-HQ 3만 장으로 학습, 눈썹·눈·입술·머리카락 등 19가지)을
서버에 넣었습니다(`OnnxFaceParser`). 2026-11-10에 여러 분할 모델을 비교해서 ResNet34 학습본(`face_parsing_bisenet_r34_fp16.onnx`, 47MB)으로 바꿨습니다(`docs/face-parsing-models.md`). 이 문서의 표는 바꾼 모델 기준이고, 아래 개선 기록의 숫자는 그때 모델 기준입니다.

- 얼굴 좌표로 돌려 맞춘 512x512로 넣고(두 눈 사이의 4.2배 정사각형), 눈썹 칸만 골라 높이·꼬리·길이·두께를 잽니다.
- 모델 파일이 없거나 눈썹 칸을 못 찾으면 예전처럼 밝기로 나눠 잽니다.
- 사진 한 장에 CPU로 70~200ms 걸립니다.
- 모델 만드는 법: `export_face_parsing.py`. 공개 Docker 이미지에서 원래 가중치(zllrunning/face-parsing.PyTorch)를 받아 ONNX(fp16)로 바꿉니다.
  모델 구조는 직접 다시 쓰고, 가중치는 코드 실행 없이 숫자만 읽습니다. fp16 결과는 fp32와 같았습니다(int8은 눈썹 모양이 달라져서 쓰지 않음).
- 눈썹 길이: 그대로 재면 고개를 10도 안쪽으로만 돌려도 먼 쪽 눈썹이 짧아 보여서(고개 각도와 상관 0.60) 거의 못 잡았습니다.
  같은 높이의 **얼굴 반쪽 너비(코 가운데 ~ 얼굴 옆선)로 나누면** 먼 쪽 얼굴도 같이 좁아 보여 상쇄됩니다(상관 0.02).
  기준이 0.475 → 0.218로 줄고, 한쪽을 많이 짧게 그린 것 검출이 2% → 42%가 됐습니다.
  눈 너비로 나누기, 꼬리 끝과 눈꼬리 사이, 고개 각도로 직접 보정하기는 효과가 없었습니다.
- 입술 반쪽 너비는 분할 모델이 밖으로 그린 입꼬리를 입술로 거의 안 쳐서(크게 그려도 비율 0.06 변화) 분할 모델로 재지 않습니다.
- CelebAMask-HQ도 비상업 연구용입니다.

## 입술 너비 (2026-11-09)

입꼬리 위치를 사진에서 재면 좌우 차이가 원래 16%쯤 흔들려서(웃음, 고개 돌림, 입꼬리 그늘) 한쪽을 밖으로 그린 것(평균 +0.175)을 잘 못 잡았습니다.
윤곽점 입꼬리는 그린 선은 거의 안 따라가고(+0.024) 웃음·고개 돌림 같은 원래 비대칭은 따라가므로, **사진 입꼬리 - 윤곽점 입꼬리**(쪽마다 "더 그린 길이")를
좌우 비교하면 흔들림이 0.16 → 0.05로 줄고 그려 넣은 차이는 남습니다. 한쪽을 많이 밖으로 그린 것 검출 20% → 41%.
코 가운데 기준, 얼굴 반쪽 너비로 나누기, 둘 섞기, 고개 각도 보정은 24~32%로 이보다 낮았습니다.
누드 립처럼 색으로 입술을 못 나누면 이 항목은 재지 않습니다(윤곽점만으로는 그린 선을 알 수 없음).

## 눈썹 두께 (2026-11-09)

분할 모델 눈썹으로 두께를 재는 5가지를 비교했습니다: 열마다 잰 두께의 가운데 값(그전 방식), 가운데 60%만, 넓이 ÷ 길이, 윤곽점 두께 대비 2가지.
**넓이 ÷ 길이(평균 두께)**가 가장 덜 흔들려서(좌우 흔들림 0.094 → 0.083) 바꿨습니다. 윤곽점 두께는 그린 두께를 전혀 안 따라가서(변화 -0.002) 빼도 나아지지 않았습니다.
기준 0.182 → 0.162, 한쪽을 두껍게 그린 것 중간 크기 38% → 45%, 가장 큰 구간 50% → 55%.

## 입술 선 (2026-11-09)

윗입술 선을 많이 넘겨 그려도 75%에서 더 오르지 않아 놓친 것을 봤더니, 입술 색 경계로 잰 두께가 원래 좌우로 크게 흔들렸습니다(p95 0.45).
같은 자리에서 윤곽점으로 잰 두께 비는 0.18만 흔들려서, 흔들림 대부분이 타고난 비대칭이 아니라 재는 방식의 잡음이었습니다.
그래서 **분할 모델이 윗입술(12)·아랫입술(13)로 나눈 칸을 입 가운데~입꼬리의 20·35·50·65·80% 자리에서 세로로 세어 두께를 재고**,
같은 자리의 윤곽점 두께 비를 빼서 타고난 비대칭을 지웠습니다(윤곽점은 넘겨 그린 선을 거의 안 따라감).

| 방식 | 좌우 흔들림 p95 | 넘겨 그림 중간(0.04~0.06) | 가장 큼(0.08~0.1) |
| --- | --- | --- | --- |
| 색 경계 두께 비(그전) | 0.445 | 36% | 61% |
| 색 경계 − 윤곽점 | 0.407 | 38% | 64% |
| 분할 모델 두께 비 | 0.238 | 75% | 78% |
| **분할 모델 − 윤곽점(지금)** | **0.182** | **80%** | **82%** |

(윗입술만 따로 기준을 잡은 비교입니다. 서버는 윗·아랫입술을 한 기준으로 묶어서 0.168이고, 그 기준으로 중간 86%, 가장 큼 94%.)
아랫입술도 흔들림이 0.262 → 0.143으로 줄었습니다. 분할 모델이 없을 때만 그전 방식으로 잽니다.

## 입꼬리 높이 시험 (2026-11-09, 바꾸지 않음)

한쪽 입꼬리를 위로 올려 그린 것(두 눈 사이의 0~0.1)을 그려 넣어 시험했습니다. 지금 방식은 10~18%만 잡고, 윤곽점 입꼬리 대비·입꼬리 쪽 윗/아랫 가장자리·둘의 가운데로
재는 5가지도 3~14%였습니다. 0.1만큼 올려 그려도 잰 값은 0.02~0.036만 움직이는데, 사진에서 잰 입꼬리 높이는 원래 좌우로 0.04쯤 흔들려서
(입꼬리 그늘, 입 모양) 구분이 안 됩니다. 이 항목은 "아주 심할 때만 말하는" 항목으로 두고, 같은 방식은 더 시도하지 않습니다.

## 한계

- CelebA는 유명인 사진이라 조명·화장이 셀카와 다르고, 서양인 비율이 높습니다. 윤곽점도 ML Kit가 아니라 MediaPipe입니다.

## 뒤집어 한 번 더 나누기 (2026-11-11)

분할 모델은 덧그린 눈썹 아래쪽을 한 방향에서만 눈썹으로 보는 일이 많았습니다(같은 사진을 좌우로 뒤집어 넣으면 다른 칸을 눈썹이라고 함).
그래서 두께만, 원래 결과와 뒤집어 나눈 결과 중 어느 한쪽이라도 눈썹이라고 한 칸을 합쳐서 잽니다. 높이·길이는 합치면 오히려 나빠져서(같은 사진 짝 놓침 8, 19) 원래 결과 그대로입니다.

| | 기준(p95) | 아주 작음 | 작음 | 중간 | 큼 | 아주 큼 | 평균 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 그전 | 0.155 | 21% | 40% | 47% | 49% | 56% | 43% |
| 합친 두께 | 0.141 | 23% | 43% | 62% | 67% | 62% | 51% |

같은 사진 짝: 새로 잡음 44, 놓침 9(부호 검정 p<0.001). 다른 항목 값은 하나도 바뀌지 않았습니다.
대가는 사진 한 장에 분할을 한 번 더 돌리는 것(약 0.1초)과 서버 메모리 약 60MB입니다.

시험해 보고 넣지 않은 것(같은 2,832장, 서버와 같은 값을 내는 파이썬 재현으로 비교):
- 눈썹 길이: 끝 위치만, 윤곽점 길이 빼기, 눈 너비·윤곽점으로 나누기, 고개 각도 회귀 등 11가지. 지금 방식(얼굴 반쪽 너비로 나눔, 23%)보다 나은 것이 없었습니다.
  지운 눈썹 꼬리의 대부분을 분할 모델이 여전히 눈썹으로 봐서(꼬리를 0.25~0.4 지워도 분할 길이는 15%만 줄어듦) 재는 방식으로는 한계가 있습니다.
- 눈썹 두께에 사진 색 더하기(분할 눈썹 아래 어두운 칸): 눈썹 밑 그늘까지 잡아서 45% → 34%로 나빠졌습니다.
- 입술 너비를 분할 모델 입술 칸으로 재기: 14%로 지금 색 방식(21%)보다 나빴습니다.

## 눈썹 길이 모델 (2026-11-11)

분할 모델은 지운 눈썹 꼬리를 여전히 눈썹으로 보는 일이 많아서(꼬리를 0.25~0.4 지워도 잰 길이는 15%만 줄어듦), 길이를 재는 방식을 11가지 바꿔도 22~23%가 한계였습니다.
그래서 "어느 쪽 눈썹이 얼마나 짧은지"를 바로 맞추는 작은 모델(CNN, ONNX 0.8MB)을 학습했습니다.

- 입력: 두 눈 기준으로 자른 양쪽 눈썹 조각(오른쪽은 좌우로 뒤집음). 같은 CNN에 넣은 점수의 차이 = 지운 비율. 좌우를 바꾸면 부호만 바뀌어서 한쪽 버릇이 생기지 않음.
- 학습 데이터: 평가에 쓰지 않는 CelebA 5,371장 × 편집 4가지 = 12,598쌍(`brow_length_data.py`, `train_pair_model.py brow_length`, CPU 약 25분).
- 처음에는 눈썹이 아니라 **지운 흔적**을 보고 있었습니다(눈썹 옆 이마만 지운 사진도 43% 잡음). 지우는 방식을 3가지로 섞고, 눈썹 근처 피부만 지운 사진과 높이·두께만 바꾼 눈썹을 정답 0으로 넣어 다시 학습했습니다.

| 확인 (평가 사진 300장, 기준 0.046) | 잡은 비율 |
| --- | --- |
| 손대지 않은 사진 | 4% |
| 이마만 지운 사진(눈썹 그대로) | 6% |
| 학습에 없던 방식(피부색으로 덮기)으로 꼬리를 지운 사진 | 85% |
| 학습과 같은 방식으로 꼬리를 지운 사진 | 99% |

서버로 같은 2,832장을 다시 잰 결과(기준 0.045): 한쪽 눈썹을 짧게 그린 것 22% → 84%, 같은 사진 짝 새로 잡음 263 / 놓침 3. 다른 항목 값은 그대로입니다.
한쪽 눈썹을 올려 그린 사진은 19%에서 길이 차이로도 봐서(그전 방식 7%), 눈썹 높이를 이미 말했으면 길이는 말하지 않게 했습니다.
대가: 사진 한 장에 모델 실행 약 2ms(조각 자르기 포함해도 수 ms), 모델 파일 0.8MB. 학습 사진이 CelebA(비상업 연구용)라 모델도 같은 조건입니다.

한계: 짧게 그린 눈썹을 사진 편집으로 만든 것이라, 실제로 펜슬로 짧게 그린 눈썹에서는 더 낮을 수 있습니다. 팀 셀카로 꼭 다시 확인해야 합니다.

## 고화질 실사진(FFHQ)으로 다시 잡은 기준 (2026-11-12)

CelebA는 작은 사진을 키운 것이라 피부·눈썹 결이 매끈하고, 화장한 여성만 골랐습니다. 실제 셀카에 가까운지 보려고

지금 서버로 쟀습니다. 정면(10° 이내)이고 잴 수 있었던 사진은 590장입니다.

- CelebA 기준으로는 손대지 않은 실사진에서 항목마다 7~18%를 잘못 알렸고, 하나라도 알린 사진이 59%였습니다(CelebA 29%).

### 2026-11-13 낮: 학습을 바꿔도 안 오름 → 틀리는 사진을 봄

4판과 같은 망·데이터에서 학습만 바꾼 세 번은 모두 61%를 못 넘음(같은 346장, TTA, 잘못 알림 5%).

| 시도 | 전체 |
|---|---|
| 4판을 6에폭 더 이어 학습 | 55.5% |
| 밝기 흔들기를 두 조각에 같이(+흐림·잡음) | 51.8% |
| 조각마다 조명 기울기·흐림·잡음 추가 | 50.5% (4판과 평균 60.1%) |

틀리는 사진을 직접 보니:
- 평가 346장 중 23%가 안경·선글라스(얼굴 분할 6번이 눈 조각의 2% 넘음). 선글라스는 편집이 아예 안 보임. 안경 사진을 빼면 같은 모델이 61% → 66%.
- 서버는 이미 눈 밑 피부 밝기 차이가 큰 사진(`uneven-light`)을 건너뛰는데, 기준 0.31은 그런 사진까지 넣고 잰 값이었음. 서버가 실제로 재는 사진만 보면 p95가 0.255.
- 머리카락이 눈 조각을 덮은 비율로 거르는 것은 효과가 없었음(66% 그대로) → 넣지 않음. 모델을 섞는 것도 효과 없음.
- 섀도 0.3·라인 0.5는 사람 눈에도 거의 안 보임. 모델 반응(편집 전후 점수 차이 평균 0.21)이 타고난 좌우 차이(표준편차 0.15)보다 작음.

그래서 서버를 바꿈: 눈 조각에 안경이 2% 넘으면 눈화장은 건너뜀(`eye-glasses`, skipped에 eyeMakeup), 기준 0.31 → 0.26.
서버로 직접 잰 값(`eye_server_eval.py`, 346장 × 6가지): 서버가 재는 사진 218장(63%), 건너뜀 126장(안경 79, 한쪽 그늘 47), 다시 찍기 2장.

| 기준 | 잘못 알림 | 섀도 0.3 | 섀도 0.5 | 섀도 0.7 | 라인 0.5 | 라인 0.8 | 전체 | 뚜렷한 것(섀도 0.7·라인 0.8) |
|---|---|---|---|---|---|---|---|---|
| 0.31 (전) | 2.8% | 35% | 69% | 83% | 57% | 79% | 65% | 81% |
| **0.26** | 4.1% | 47% | 76% | 88% | 66% | 82% | **72%** | **85%** |

p95를 218장으로 정해서 흔들림이 있음(부트스트랩 10~90%: 0.243~0.269). 모델은 4판 그대로.
